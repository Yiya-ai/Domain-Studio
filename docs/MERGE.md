# 合并实施与验证记录

日期：2026-11-03（Asia/Shanghai）。

## 实施范围

以本地 Domain-Hunter `40ac90f` 的完整前端、生成器、价格、收藏、社交、过期列表、CLI/MCP 为基础，保留原始源码与锁文件到 `frontend/`。以 domain-check `c137e60` 的 Go 引擎与 API 为应用根目录，包含原本地补齐的资源监控模块。未复制原 Git 历史、CI、日志、个人查询结果或运行数据库；原两个项目未改动。

统一程序为 `bin/domain-studio.exe`，首页是嵌入的 Svelte 应用；原 Go 页面移到 `/legacy`。没有 iframe 拼接、没有运行时引用父级原项目，也没有新增第三方依赖。

浏览器引擎与 Go 引擎通过同源 `/api/v1/check` 对接。只有 Go 实际提供的页面才会注入后端标记，直接打开便携 HTML 不会探测后端。CSP 同时允许原应用的 HTTPS 数据源、同源 HTTP API 和内联 Worker。原 API 的请求体限制、限速、超时、健康检查与指标保留。

新增“后端与监控”：引擎选择、健康状态、注册信息详情、收藏域名建议、持久监控创建/状态/取消、带密钥备份导出与导入。新增 `GET /api/v1/watch/{id}` 使用 `X-Watch-Secret` 验证，返回值清除密钥和客户 IP；没有匿名公开的任务列表。新增界面有中文和英文，原其他语言显示英文新增文案。

## 正确性修复

- 查询适配器保持五种原状态；低可信 RDAP、WHOIS、来源未知的缓存不会被抬高为确定可注册；DNS 缺失、HTTP 错误、响应域名不一致、异常响应均不会报可注册。
- 对后端 429 遵守 `Retry-After`，等待可取消；取消队列时保留已完成的结果并正确结束进度；旧 Worker 任务不能向新任务串入结果。
- DNS 错误不再作为注册证明返回，不缓存这种错误结果；提前取消的 DNS 请求直接返回取消错误。
- 监控初次状态从 `unknown` 开始，第一次检查只建立基线；错误结果不改变基线。
- 修复 Windows 时间精度导致连续同类崩溃转储覆盖的问题，文件名增加序号。
- 原后端两个 mock 耗时测试改为允许合法的零耗时，避免 Windows 时钟分辨率导致误报；没有删除功能断言。

## 数据迁移

检查原 `domain-check/data`：只有历史诊断目录，没有 `watches.db`，因此没有自动迁移服务监控任务。

浏览器的 8081 与 8082 是不同 origin。旧收藏、历史等不会自动迁移，也不会被删除。若要完整迁移：

1. 打开旧 Domain-Hunter 网页 `http://127.0.0.1:8081/`，在浏览器开发者工具 Console 中运行 `scripts/export-browser-data.js` 的内容，下载 JSON。
2. 打开新 Domain Studio `http://127.0.0.1:8082/`。如新项目已有数据，先在此执行导出脚本留一个备份。
3. 在新页面 Console 中运行 `scripts/import-browser-data.js`，选中旧备份并确认。导入会恢复 `dh:v1:*` 数据并刷新。

这些脚本只下载/读取本地 JSON，不发送网络请求。发布版脚本排除 GitHub token 和监控管理凭据；查询历史和收藏仍属于私有数据。旧备份导入时也会去除 GitHub token。浏览器备份用脚本导入，原设置/词集 JSON 用“设置 → 导入”，监控凭据单独使用“后端与监控 → 导入监控备份”。

合并过程没有读取或迁移浏览器中的用户数据；上述是按需操作方法。

## 保留的边界

两套命令行工具均保留：Go CLI 负责查询/批量/轮询监控；Node CLI/MCP 负责原 Domain-Hunter 工具。MCP 暂未新增持久监控工具，持久监控可通过统一 HTTP API 调用。

监控服务必须运行；网站/HTML 本身不能在关机后继续监控。外部注册局可能限流，价格快照可能过期，社交检查依赖各平台公开接口与原有配置。原资料中关于纯浏览器产品的描述见 `frontend/SPEC.md`，合并扩展以项目根 `AGENTS.md` 和本文件为准。
